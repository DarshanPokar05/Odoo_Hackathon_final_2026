# DealFlow360 — API Contracts

> **Purpose:** This file is the single source of truth for every HTTP endpoint and Socket.io event in the DealFlow360 platform.
> Both the frontend dev and backend dev must append to this file as each module is implemented.
>
> **Conventions:**
> - All REST endpoints are prefixed `/api/`
> - Authentication: `Authorization: Bearer <jwt>` header unless marked `[PUBLIC]`
> - All request/response bodies are JSON unless noted
> - Timestamps are ISO-8601 strings
> - Paginated list responses follow `{ success: true, data: { items: [], total, page, limit } }`
> - Error responses follow `{ success: false, error: { code, message, details? } }`
> - Success responses follow `{ success: true, data: <payload> }`
> - CUSTOMER-role tokens carry an additional `customerId` claim and are scoped to their own data
>
> **Socket.io** — authenticate by passing `{ auth: { token: "<jwt>" } }` on connect.
> Rooms joined automatically: `user:{userId}`, `role:{role}`, and `customer:{customerId}` (CUSTOMER role only).

## Auth — `/api/auth`

_Implementation: `src/modules/auth/`_

| Method | Path                       | Auth    | Roles | Description |
|--------|----------------------------|---------|-------|-------------|
| POST   | `/api/auth/signup`         | PUBLIC  | —     | Create internal user (ADMIN, SALES_REP, SALES_MANAGER, FINANCE only). Body: `{ name, email, password, role? }` |
| POST   | `/api/auth/login`          | PUBLIC  | —     | Login. Returns `{ token, user }` or `{ mustChangePassword: true, userId }` for first-time portal customers |
| POST   | `/api/auth/change-password`| PUBLIC  | —     | Complete forced password change. Body: `{ userId, newPassword }`. Returns `{ token, user }` |
| GET    | `/api/auth/me`             | JWT     | ALL   | Return current user profile |

**Signup notes:**
- `role` defaults to `SALES_REP` if omitted
- `CUSTOMER` role is rejected — portal accounts are auto-generated by the customer onboarding flow
- Returns `{ user, token }` on success (201)

**Login notes:**
- If `mustChangePassword = true`, no token is issued; client must call `/change-password` first
- Token payload: `{ userId, email, role, customerId? }`

## Quotations — `/api/quotations`

_Implementation: `src/modules/quotations/`_

| Method | Path                                     | Auth | Roles                                              | Description |
|--------|------------------------------------------|------|----------------------------------------------------|-------------|
| GET    | `/api/quotations`                        | JWT  | ADMIN, SALES_REP, SALES_MANAGER, FINANCE           | List quotations (filtered by rep for SALES_REP) |
| GET    | `/api/quotations/:id`                    | JWT  | ADMIN, SALES_REP, SALES_MANAGER, FINANCE, CUSTOMER | Get quotation with lines, steps, messages |
| POST   | `/api/quotations`                        | JWT  | ADMIN, SALES_REP                                   | Create draft quotation |
| PUT    | `/api/quotations/:id`                    | JWT  | ADMIN, SALES_REP                                   | Update quotation |
| DELETE | `/api/quotations/:id`                    | JWT  | ADMIN                                              | Delete quotation |
| POST   | `/api/quotations/:id/submit`             | JWT  | ADMIN, SALES_REP                                   | Submit for approval (triggers blended risk score + approval chain) |
| POST   | `/api/quotations/:id/confirm`            | JWT  | ADMIN, SALES_MANAGER                               | Confirm approved quotation → creates Order |
| POST   | `/api/quotations/:id/negotiate`          | JWT  | ADMIN, SALES_REP, CUSTOMER                         | Send negotiation message |

### Socket.io Events

| Event               | Direction      | Payload                                | Description |
|---------------------|----------------|----------------------------------------|-------------|
| `QUOTATION_UPDATED` | Server→Client  | `{ quotationId, status, ...extra }`    | Status change — pushed to rep's room, role:SALES_MANAGER, role:FINANCE |
| `NEGOTIATION_MESSAGE` | Server→Client | `{ quotationId, message, senderType }` | New negotiation message — pushed to rep + customer:{customerId} |

## Socket.io — Room Reference

| Room                    | Who joins              | Events received |
|-------------------------|------------------------|-----------------|
| `user:{userId}`         | Every authenticated user | Personal notifications, approval actions, quotation updates |
| `role:{role}`           | Every authenticated user | Role-wide broadcasts (e.g. approval queue, deal health flags) |
| `customer:{customerId}` | CUSTOMER-role only     | Portal quotation/negotiation/invoice updates |
